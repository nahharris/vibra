# M3 review fixes

After Step 18 an adversarial review of the `m3` → `main` pull request ran
seven scoped reviewers over the milestone. Every finding listed here was
reproduced with the toolchain before it was accepted. Steps 19 onward fix
them; each fix lands with a corpus case that fails without it.

These steps correct the implementation against the specification. Where the
specification itself changes, the step names the ledger row.

| Step | Fixes | Cases | PR |
| --- | --- | --- | --- |
| 19 | Runtime shapes. A payload slot instantiated to `void` had two runtime shapes, so generic code over `(result void e)` trapped and `try` over a nullary success failed; a tail-position call whose result is widened failed at run time; a tuple-bodied `deftype` key ignored its own `ordered`; a binder on a `void` `enumof` payload was an internal error; a `void` operand that fixes an open payload was accepted | `V1-RUNTIME-void-payload-shapes`, `V1-RUNTIME-widened-tail-call`, `V1-RUNTIME-tuple-user-key`, `V1-TYPE-NOMINAL-void-payload-operand` | #336, merge `b251782` |
| 20 | Interface checks. A bounded generic function or lambda used as a value never had its bound checked; a default member's own `where:` bounds were dropped (a valid body rejected, a violating call accepted, an unknown bound ignored); a default member with a second `self` operand, and a member whose result takes `self` as a function operand, were callable through an interface value and trapped; an abstract contract member named as a function value ran a placeholder body. A member selected by its destination, of a generic interface, or with generic, labelled, or variadic parameters is not yet a function value and reports `@tool.unavailable` | `V1-RUNTIME-contract-member-values`, `V1-TYPE-INTERFACE-value-bounds`, `V1-TYPE-INTERFACE-self-through-value` | #337, merge `05fb272` |
| 21 | Unions. An anonymous union's discriminant is its canonical member position, which changed when a generic parameter inside a member was substituted, so the wrong `as` arm matched and the program trapped: a member of an anonymous union now names no generic parameter (D26.1). The finite-size check skipped anonymous unions; an anonymous union of admissible keys was rejected as a dict key and had no `ordered`; a written expected union type did not reach generic inference, so a generic declared union needed `types:` at every construction; and two union members that no single substitution makes equal were reported as overlapping | `V1-RUNTIME-union-keys`, `V1-TYPE-NOMINAL-union-generic-member` | #338, merge `60fdc3b` |
| 22 | Generic instantiation at run time (D27.1). The interpreter erased generics, so a receiver implementing a generic interface twice answered with the first declared implementation, a value built inside a generic function kept the parameter in its type and matched any implementation, and a default member could not dispatch at its own interface arguments. Activations now carry their type arguments, values have instantiated types, and typed IR records the interface arguments of an implementation and of a contract call. A member selected by its destination is now accepted when the destination is a parameter bounded by the interface, where it reported a false unsatisfied bound | `V1-RUNTIME-generic-dispatch` | #339, merge `081015d` |
| 23 | Call-flow analysis. The typed IR's operand walk skipped a widened expression, and its child walk skipped `match` arms, so a module-value cycle through a widened call or a function named in a match arm was not detected and trapped, and a tail loop reached only through a widened call exhausted the stack. `array.fold` was not treated as invoking its step function (an undetected cycle, tail recursion not reused, and a valid program rejected with an internal error). A function value passing through a generic parameter lost its call edges. One test whose program failed to build made every later test a trap | `V1-RUNTIME-tail-calls-through-flow`, `V1-TYPE-NAMES-initializer-cycle-widened`, `V1-TYPE-NAMES-initializer-cycle-match-arm`, `V1-TYPE-NAMES-initializer-cycle-fold`, `V1-TYPE-NAMES-initializer-cycle-generic` | #340, merge `faedf1e` |
| 24 | Runtime results and library. `iter.skip` and `iter.filter` exhausted the activation bound after about 4,090 discarded items; a repeated dict key kept the earlier key with the later value; `vibra run` aborted with a stack overflow when the entry's result was nested a few hundred levels deep; an entry error type holding a function was accepted and then failed at run time; a test module could import `@std.builtin`, after which every test trapped. The type chapter's rule that an `iter` owner must be generic over its item was stale and is corrected | `V1-RUNTIME-iter-skip-filter-depth`, `V1-RUNTIME-dict-repeated-key`, `V1-PROJECT-workspace-check-entry-function-result`, `V1-PROJECT-workspace-test-builtin-import`, `process_review_fixes` | #341, merge `b32d9cb` |
| 25 | Order-independent inference (D28.1). `match` took the first arm's type as the expected type of later arms, so widening, literal typing, and a destination depended on arm order, unlike `if`. A generic call checked operands left to right, so `(pick 2i32 1)` was accepted and `(pick 1 2i32)` was not, and an operand widened to a type a sibling operand had fixed. An unsuffixed literal chose a conversion source by its value. `as` over `if`, `let`, or `do` reported `@type.mismatch` instead of `@type.invalid-ascription` | `V1-RUNTIME-inference-order`, `V1-TYPE-INFER-order-independence`, `V1-TYPE-CONVERT-ascription-through-forms` | #342, merge `d04cc09` |
| 26 | Names and diagnostics. A private member was reachable across modules through a single-declaration import alias; `any`, `option`, `result`, and `iter` could be redeclared; an atom was rejected as a labelled default, so one of the source chapter's own examples did not parse; a type named as a bound reported an unknown name instead of the wrong kind of entity; the non-exhaustive witness was not the first uncovered shape, and a `str` witness was misspelled | `V1-PROJECT-workspace-check-declaration-alias-member`, `V1-TYPE-NAMES-reserved-role-names`, `V1-RUNTIME-atom-labelled-default`, `V1-TYPE-GENERIC-bound-wrong-kind`, `review_m3_step26` | #343, merge `7097285` |
| 27 | Tooling. `@index.v1` paired a member with its formatted text by position, so a type that wrote an `impl` block before a method swapped the two records' `text`; a reference in a test body named `from` as an identity that is not VIBON. The position query left a variadic parameter out of `visibleLocals` while reporting the list as exact. The formatter moved a comment written on a form's line onto the next form; ordered union members by their written spacing, so its output was not stable; treated a parameter list whose first parameter is named `union` as a union type and refused the file; skipped the canonical attribute order in any file holding a comment, and did not know `role:` or `native:` there; and left closing delimiters alone on a line after a header list at exactly 89 columns | `V1-TOOL-index-member-order`, `V1-TOOL-index-test-references`, `V1-TOOL-workspace-position-variadic`, `V1-TOOL-format-comment-placement`, `V1-TOOL-format-type-positions`, `comment_layout` | #344, merge `314862c` |
| 28 | Observation (D29.1). A function hidden behind `any`, an interface, or an iterator reached the value encoder in `assert.equal` or in the entry's result and was reported as `@runtime.invalid-checked-program` with no location, the code of a toolchain invariant failure: it is now the trap `@runtime.unobservable-function`, located at the assertion call in a test and reported as `@command.trap` by `run`. Function types were encoded as `(fn …)` instead of the specified `(record type: @fn …)`; the encoding now follows the runtime chapter, which gains the `variadic:` field and the name order of labelled parameters. The corpus manifest admits a runtime trap diagnostic on an accepted case | `V1-RUNTIME-workspace-test-hidden-function`, `process_review_fixes`, re-blessed `V1-TOOL-index-*` and `V1-SRC-CALLS-functions-labelled` | #345, merge `7a44bcf` |
| 29 | Documentation and evidence. Two examples in the type chapter did not check (`parse-port` converted from `str`, which has no registry conversion; `array.first` is not a member) and are replaced by ones that do. The Step 17 rename had turned the `iter` member `map` into `dict` in two roadmap sentences. Float `from`/`try-from` was listed as reassigned to M4, though the type chapter gives floats no conversion in v1: the row is removed. D22.2 said the contract-member forms were deferred past v1 while the exit evidence said M4: both now say M4. Stale text is corrected (S1 `tuple.of`, D3.1 and the roadmap's `hashable`, the type chapter's status line, one evidence span, one removed case cited as live). Six evidence rows named a case that did not show the stated behavior; the behavior was correct, and each now has its case | `V1-TYPE-GENERIC-bound-overlap`, `V1-RUNTIME-factory-self-tail`, `V1-TYPE-CONVERT-factory-destination`, `V1-RUNTIME-interface-widening-positions`, `V1-TYPE-NOMINAL-intrinsic-type-user`, `V1-TYPE-GENERIC-reserved-names` | #346 |

## Confirmed and not fixed

The review confirmed these too. None gives a wrong answer at run time: each
is a wrong diagnostic code or span, a missing check whose effect cannot be
observed yet, or a form that reports `@tool.unavailable`. They are listed so
that the milestone's exit does not claim them.

| Finding | Behavior now | Specification |
| --- | --- | --- |
| A value, function, or module named where a type is expected | `@name.unknown-symbol` | `@name.wrong-entity-kind`; Step 26 fixed only the bound position |
| `(array)`, `(array i32 i32)`, `(dict i32)`, bare `array` as a type | A syntax or unknown-symbol diagnostic | `@type.type-argument-mismatch` |
| A literal `str` arm after an arm that covers every string through `(str (array …))` | Accepted | `@pattern.unreachable-arm` |
| `equatable` on a tuple or structure holding a user key type | No implementation found | The builtin conformance covers tuples of admissible keys |
| An implementation member whose labelled default differs from the contract's | Accepted | Implementations preserve labelled names and defaults; unobservable while labelled contract calls are unavailable |
| `@type.invalid-dict-key` and `@type.union-member-overlap` spans | The owning parameter or whole `deftype` | The key type expression and the union type expression |
| `@type.infinite-size` through a tuple and an enum in mutual recursion | The related span repeats the primary span | The member through which the type repeats (D3.3) |
| `(as (tuple …) (tupleof …))` with a mismatched component | A component mismatch code | `@type.invalid-ascription` |
| The non-exhaustive witness for a record with a `bool` field | `(recordof a: false b: -)` | The witness spelling of the pattern chapter |
| A `lambda` with attributes in a noncanonical order, in a file that holds a comment | Left as written | The canonical attribute order |
| A contract member named as a function value when it is selected by destination, belongs to a generic interface, or has generic, labelled, or variadic parameters | `@tool.unavailable` | Member paths are first-class; Step 20 implements the plain abstract member |
| An interpreter invariant failure in `run` | `@command.operational-failure` | `@command.trap`; Step 28 moved only the unobservable-function trap |
| `(id (as any 1i32))` with `where: (t any)` | Accepted | Ambiguous: an interface value type never satisfies a bound, and every type satisfies `any` |
