# v0.0.4 M1 — Libraries and agent adapters

Status: planned. Prerequisites: v0.0.2 snapshots, protected approval, query/eval/test/edit engine and exact input identity. Native completion is not a prerequisite for resolving a library or implementing an adapter.

| Step | Complete slice | Required evidence |
| --- | --- | --- |
| N4.1.1 | Exact local/Git dependency acquisition and locks. | Canonical package/unit identity, no package/import cycles, exact revisions, stale/missing/tampered lock denial, path confinement and offline repetition. |
| N4.1.2 | Indispensable typed integration. | A real dependency through explicit types, conversions and authority/model boundary; typed failure and driver/policy provenance. |
| N4.1.3 | Upgrade and repair. | Change pinned revision, classify public claim/nominal/authority changes, reject stale approval, repair a real failing protected test and record effort. |
| N4.1.4 | Thin MCP adapter. | Identical pinned query/eval/test/edit facts, statuses and revision preconditions to machine CLI; malformed/stale/denied and bounded-output cases. |
| N4.1.5 | Selected editor/LSP client. | Navigate failure, inspect callee/row/driver, preview revision-checked edit and rerun selected tests over the shared engine. More clients require actual acceptance evidence. |

## Gate

Use, pin, inspect, upgrade and repair a real dependency under the supported offline/local story. Protect oracle bodies/fixtures/selection/runner and distinguish candidate code; pin both per run. Integration/conversion/model costs and unsupported features are explicit, not an effortless-ecosystem claim.

Machine schemas, diagnostics and source/version identities agree across adapters and CLI. Both suites pass. No adapter reinterprets source with its own checker.

## Exclusions

No registry, SemVer range solving, dependency lifecycle scripts, arbitrary FFI, automatic driver trust, five-editor prerequisite, live redefinition or stage/publish database workflow.
