# Native target and toolchain qualification

Status: planned for the rewritten K3 native profile, not a carried-forward pass record.

## Starting evidence and limits

The tree contains Cranelift/object/bridge/link scaffolding, Windows-only vibra-build support and old-profile fixture tests. They are starting points. Former Windows observations did not qualify Linux/macOS or new guards/grants/entry. Reproduce applicable cases before recording a current pass. Shipped v0.0.1 evidence remains untouched.

## Required record

Per target record tested commit, host/target OS/architecture, Rust/Cranelift versions, CPU/ISA flags, object format, linker/compiler driver/SDK/system libraries, archive identity, explicit environment, argument vector, exit status and output. Mark unexecuted items not run.

## Qualification steps

1. Emit an object calling a real bridge symbol, link with the real archive and launch success plus deliberately failing expected-result variants on the target.
2. Check explicit target/CPU baseline, no host-native CPU guessing, and structured missing ISA/target failures.
3. Exercise missing/wrong linker version, absent archive, Unicode/space paths, long argument lists and actual static-library requirements. Record discovery independently of PATH.
4. Run K3 entry/ExitCode and required/optional startup grant binding. Reject ABI/registry/driver/world/policy mismatch before main and before host action.
5. Compare checked-error/origin/audit observations against interpreter/stepper, quota one and unbounded. A user input error is not an engine-trap fixture.
6. Pin inputs and repeat clean offline builds from different checkout paths. Explain differences; do not normalize unexplained bytes away.

Windows filesystem confinement feasibility is a separate v0.0.2 M0 prerequisite. These link tests do not prove useful allowed file access plus rejected reparse/name/race attacks.

## Acceptance

Each supported target needs a launched executable and machine-readable independent expected observations. Cross-emitted headers are not execution evidence; unavailable runner stays pending. An always-refusing adapter is safe but not a useful program-gate pass. No qualification was run for this rewrite.
