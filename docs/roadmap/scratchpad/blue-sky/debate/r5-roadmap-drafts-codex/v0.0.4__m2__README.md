# v0.0.4 M2 — Concurrency semantics and simulation

Status: planned. Specification prerequisite freezes source/library and machine contracts before widening programs. Existing partial vibra-actors lifecycle machinery is not source-profile qualification.

## Prerequisite contract

Specify scoped spawn/join/cancel cleanup, bounded ordered parallel map, receive-loop actor lifetime, transferable values/captures/grants, typed protocol operation sets, mailbox bounds/order, full/closed/refused send, reply slots/duplicate replies, exit while waiting, timeout and blocked execution. Define target admission of every startable body's host requirements and causal send-to-handler-to-host reports. No unapproved placeholder API is advertised.

| Step | Complete slice | Evidence |

| N4.2.1 | Shared kernel and simulation. | Bounded per-sender/receiver FIFO, one activation owner, virtual time, deterministic actions and each waiter resolved at most once. |

| N4.2.5 | Interpreter/replay integration. | Real source parks at kernel actions; expected outcomes/origins; impossible/truncated/leftover schedules are replay errors. |

## Gate

Each kernel rule has source-level success and rejection/typed-failure cases. Seeded schedule campaigns state finite domains/assumptions and do not prove every interleaving. Include self-send, full/closed mailbox, duplicate reply, actor exit, timeout, blocked state and no-actor regression. Dependency DAGs do not prohibit runtime wait cycles.

Both suites and schemas/diagnostics pass for the supported profile. Specify APIs before implementation; source forms are not invented by a test stub. Passing the kernel gate does not establish service recovery.

## Exclusions

No distribution, native-worker speed claim, durable journal, revocation, linear reply ownership or rollback of external effects.
