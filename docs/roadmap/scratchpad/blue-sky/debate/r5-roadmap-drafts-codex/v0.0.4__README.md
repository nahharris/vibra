# Vibra v0.0.4

**Planned pre-alpha release.** Libraries and bounded local concurrency follow native qualification. A shared actor kernel is the substrate; scoped child/join and bounded ordered pure parallel map are first user-facing library paths. Exposed actors are receive loops with explicit lifetimes, not a requirement that every CLI author design a mailbox protocol.

## Dependencies and specification prerequisites

Use [execution.md](../execution.md) and [Nexus packages](../nexus/plan-v0.0.4.md). Library/adapter work can start when its own v0.0.2 snapshot/tooling prerequisites pass; it does not logically require code generation. Native workers require qualified v0.0.3 execution. Record overlap explicitly and do not advertise incomplete support.

Before concurrency code, update language/type/effect/runtime/tooling/conformance contracts with exact source/API shapes, diagnostics and schemas. This plan schedules those prerequisite decisions, not permission to invent syntax in implementation. Import/build DAGs do not prove absence of runtime wait-for cycles.

## Required boundaries

- Host-resource grants/closed ceilings already exist from v0.0.2. Actor endpoints extend the sealed envelope with a disjoint target kind and kernel dispatch.
- One kernel owns lifecycle/mailboxes/protocol authorization/replies/timers/events; interpreter and Nexus drive it. A receive-loop activation can park and has one owner at a time.
- Scopes bound fan-out and define join/cancel/cleanup at exit. Cancellation after external submission does not roll back the operation; unknown/late results remain explicit.
- Ordered parallel map has an explicit bound, stable output order and sequential fallback. Purity does not promise speedup or bounded memory. Callable code/capture transfer needs its own checked rule; a blanket no-function message rule cannot silently disable mappers.
- Initial workers: fixed OS-thread pool, placement before initialization, pinned exclusive contexts, no stealing/migration. RC stays non-atomic. Messages copy neutral data; grants delegate through the broker, never arena-offset persistence.

## Release gate

Gate 2 integrates and upgrades a real dependency, recording conversion/model/assurance costs and authority boundaries. Concurrency cases cover nested bounded fan-out, early failure, cancellation before/after dispatch, late reply, backpressure, timeout and exit while waiting. Full/closed mailboxes and duplicate replies have typed outcomes, not a must-reply proof.

Recorded simulation schedules replay on interpreter and native targets with equal outcomes, message/host events and origins. Invalid/truncated/leftover schedules explicitly fail replay. Production multicore traces need not equal simulation event order; they must preserve the promised order/safety contract. Separate hardware evidence demonstrates overlapping progress on at least two workers.

Both suites and schema/diagnostic/approval regressions pass before tagging. No benchmark or scheduler qualification is asserted by this rewrite.

## Exclusions

No distribution, live migration, stealing, implicit shared heaps, affine/linear must-reply protocol, universal deadlock freedom, exactly-once external effect or crash recovery. [v0.0.5](../v0.0.5/README.md) qualifies service behavior and selected recovery. Native UI remains future work.
