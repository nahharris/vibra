# Vibra v0.0.3

**Planned pre-alpha release — no rewritten-profile gate is complete.** Vibra compiles the supported K3 language to native executables through verified execution IR, Cranelift and Nexus. The interpreter stays permanently as reference semantics and the engine for run, test, evaluation and eligible compile-time pure interpretation. Wasm is retired at this release's qualified native cutover.

| Order | Milestone | Required evidence |
| --- | --- | --- |
| M1 | [Complete native lowering and runtime profile](m1/README.md) | Every admitted K3 feature runs through verified lowering, stepper and native code, with ownership and boundary rejection cases. |
| M2 | [Three-platform qualification](m2/README.md) | Actual Windows x64, Linux x86-64 and macOS arm64 processes match independent expectations and interpreter observations; no pending executable case. |
| M3 | [Reproducible distribution and cutover](m3/README.md) | Native build/manifest, clean offline reproducibility, clean-machine install/build/run, audits and coordinated Wasm removal. |

## Dependencies and starting point

The [v0.0.2](../v0.0.2/README.md) M0 specification prerequisite establishes K3, static obligations and explicit consequences, closed ceilings, sealed grants, entry binding and identities. Its M4 supplies a revised native vertical slice. M1 completes that slice rather than lowering discarded forms. The [Nexus design](../nexus/design.md) owns the decomposition; it cannot supersede [the specification](../../spec/00-charter.md).

Existing vibra-exec, vibra-lower, vibra-nexus, vibra-nexus-eval, vibra-codegen, vibra-nexus-bridge and vibra-build contain partial native work for the preceding profile. Their presence and old Windows link observations are not evidence that K3 guards/grants/entry pass. Requalify every retained behavior through the current corpus and [target qualification](m1/feasibility.md).

Source files and immutable workspace snapshots remain authoritative. The portable semantic-input digest comes from a closed snapshot and pinned dependencies, claim/witness and policy identities, not a published database revision or authoritative content store.

## Supported targets

| Platform | Triple | Required product/toolchain |
| --- | --- | --- |
| Windows x64 | x86_64-pc-windows-msvc | PE/COFF, runtime archive, explicitly discovered/pinned MSVC and SDK link inputs, direct executable launch. |
| Linux x86-64 | x86_64-unknown-linux-gnu | ELF, runtime archive, pinned compiler-driver/link environment, actual Linux launch. |
| macOS arm64 | aarch64-apple-darwin | Mach-O, runtime archive, pinned Apple SDK/compiler-driver/link environment, actual arm64 launch. |

Windows is first in engineering order. Cross-emitting an object does not qualify its target. Unsupported target/toolchain conditions use the closed diagnostics, never a silently selected host target.

## Release gate

The complete supported native-v1 executable profile must agree on canonical results, typed errors, test outcomes, origins, startup and ordered completed-call audit projections. Compare independently authored specification expectations with interpreter-v2, stepper and native on fresh equivalent worlds. Each sequential native comparison runs unbounded and with checkpoint quota one; yielding must not duplicate dispatch or alter observations.

Gate 1 closes only when a real file-validation/transform program is created, inspected, repaired, checked, tested, built, distributed and run on clean Windows with arguments/streams/scoped files, optional/required grants, typed failures, application exit status and pinned dependencies. A development interpreter run is not distribution evidence.

M2/M3 require zero pending executable-profile cases on all three targets, both suites, schema validation and v0.0.2 repair/approval regressions. Unsupported/not-run is a gap. Before cutover keep only the declared wasm-transition-v2 profile over the retained old ABI: K3 source only, explicitly unsupported new grant/guard/entry behaviors are gaps, never invented Wasm-v2 support. Do not build a new full Wasm capability ABI for a retired backend. At qualified cutover remove active Wasm contracts, profile, emitter, runner, dependencies and packaging together. The interpreter remains.

If a platform cannot qualify, the release remains incomplete until an explicitly reviewed support-plan change. Readiness gates determine timing, not whether native compilation or Wasm retirement will happen.

## Exclusions and evidence

No GPU, remote execution, arbitrary FFI, public native-library ABI, cross-compilation product, debugger, speculative optimizer or service-recovery guarantee. Concurrency follows in [v0.0.4](../v0.0.4/README.md), services in [v0.0.5](../v0.0.5/README.md). Safety is a trusted-toolchain/runtime obligation, not OS confinement of arbitrary foreign machine code.

Use [execution.md](../execution.md) and [Nexus validation](../nexus/validation.md): complete vertical steps, diagnostics/schemas, host tests and independent Vibra cases. No new gate evidence was produced by this rewrite. Shipped [v0.0.1](../v0.0.1/README.md) evidence stays unchanged.
