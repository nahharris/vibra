The previous 886-versus-560 character comparison does not isolate the cost of keywords. Binding nesting, closure grammar, calls, and formatting differ. The proposed K correction addresses a real mismatch, but does not by itself demonstrate why any entire size difference occurred.

R1 C3's grammar argument also needs narrowing. Python 3.14 documents a lexical stack that emits `INDENT`/`DEDENT` and a parser consuming the resulting tokens; its block rule uses those tokens. Thus layout-aware tokenization can feed a token-stream grammar, rather than indentation itself forbidding grammatical parsing. [Python 3.14 lexical analysis](https://docs.python.org/3.14/reference/lexical_analysis.html#indentation), [Python 3.14 grammar](https://docs.python.org/3.14/reference/grammar.html). CPython's published full grammar is PEG, so these sources do not establish that all Python syntax is context-free. A raw-character constrained-decoding API and a layout-aware lexical runtime have different obligations. Explicit closers may simplify streaming constraints, but neither blanket provider impossibility nor a universal closer advantage follows; exact decoder support would require provider-specific verification outside this pilot. ## Freeze semantics before surface spellings

Specify a small experimental language independently of active Vibra. Every surface shares the same immutable values, integer arithmetic, division behavior, evaluation order, conditional laziness, list indexing failures, result/option constructors, pattern matching, lexical scope, recursion, closures, contracts, refinements, and transform operations. Define each explicitly rather than importing unspecified behavior from a card or an older implementation. Persistent data, effects, concurrency, and unimplemented proof machinery are excluded unless deliberately added to all conditions.

P is a controlled S-expression rendering of this experimental subset. Calling it “today's P” would imply coverage of the active language's full syntax and semantics; that claim is not part of this experiment. An optional faithful-active-language condition must be named separately and its additional features treated as a bundle comparison.

Publish one canonical reference algorithm/AST per task. All supplied examples, edit inputs, and reference answers are rendered from those ASTs. Participant answers may use a different valid algorithm and still pass the semantic endpoint; report whether they match the reference algorithm as a separate descriptive measure. Requiring reference-AST equality for acceptance would penalize legitimate programs. For direct size comparisons, use only matched reference-AST renderings, not different generated algorithms.

X1 crosses four structural shapes (D draft lines, K sections/typed closers, P structural prefix, B braces) with two leaf-call spellings: prefix `(callee a b)` and conventional `callee(a, b)`. This includes explicitly named hybrid conditions; it is not a claim that a hybrid is today's P. Primitive arithmetic/comparison remains named calls in both X1 levels. Every combination must express the same AST. This 4×2 design separates structural shape from expression/call notation; report interactions rather than pooling them into a single shape ranking. If hybrids cannot be specified cleanly, amend the design before runs or label the natural D/K/P/B comparison as bundled and unable to identify the separate effects.

X2 then compares named operator calls against infix operators with fixed conventional nonoperator calls. Precedence and the policy for mixed operators must be identical across D and K. Do not compare a prefix arm with mandatory parentheses against an infix arm with an independently relaxed grouping rule and attribute the whole difference to operator direction.

For X3, reuse the same parameter names, ordered semantic argument positions, types, and intended values. Freeze positional and labeled call permutations, omissions, and mixed-call rules. Declaration-controlled labels may alter surface metadata, not the underlying function's semantic signature. Valid permutations must normalize to the same call AST; malformed permutations have a predetermined diagnostic category. Type-checking and proof obligations are reported separately from runtime tests.

For X4, a named helper used solely as a transform callback and an anonymous lambda have identical parameters, capture-by-value behavior, and body. Both lower to the same nonrecursive closure node. Keep recursive helpers named in both arms unless the lambda arm explicitly gains an equivalent recursive binding construct; otherwise that comparison changes expressiveness. For X5, annotation omission cannot silently disable refinement checks or alter numeric defaults. Contract/proof acceptance is a distinct endpoint; successful runtime examples are not proof discharge.

The initial common checker does not include a general solver. T5 therefore tests explicitly registered refinement constructors and partial-operation safety rules, with separate checker and runtime outcomes. T6 may parse arbitrary `ensures` text/expressions as a syntax condition, but unsupported obligations are reported as unsupported/unknown. Runtime examples and hidden cases can test the contract at those inputs only; they cannot establish its universal validity. Do not grade arbitrary contract syntax acceptance as proof acceptance or count a solver-less finite test suite as universal evidence.

## Tasks, contexts, models, and budget

Freeze ten tasks and IDs: T1 nested conditional; T2 variant/match; T3 list recursion; T4 transform pipeline; T5 refinement; T6 contract/examples; T7 option chain; T8 long function; T9 edit; T10 interrupted completion. Publish exact semantic requirements. For T8, select a reference program with at least forty nonblank lines under the registered formatting convention; do not force participants to pad their solutions. Freeze task difficulty and input size before exposing any model output.

A participant context contains exactly one task, one experimental condition, one seed, and the corresponding card. It contains no previous completion, result, competing surface, hidden test, or other task. Three participants solving all ten tasks in the same context would give only three dependent sessions per surface and allow transfer between tasks. Instead use seeds S1/S2/S3 separately within every task-condition cell, with fresh sessions and recorded randomized run order. Match seed and task across conditions where the provider supports seeds; label seeds as run IDs if actual generation seeds are unavailable. Three runs remain a feasibility pilot, not persuasive evidence of equivalence or general superiority.

With 24 reusable controls per secondary arm, the maximum unique total is 360 contexts per family, or 720 for two families. If a control's task/card/settings change, it is no longer reusable and the registered count must increase before runs. This budget excludes X6 and any reruns for transport failures. Start with X1 only if the larger budget is unavailable, and defer the other arms explicitly.

Two distinct model families are a replication target, including a smaller model only if available and authorized. This agent will not spawn agents or choose an override in this round. If an authorized smaller model or second family cannot be obtained, report the missing condition and restrict the conclusion to available models; do not rename a different reasoning setting as a smaller model.

Before runs, publish exact provider, full reported model ID/version or snapshot, family, access method, generation seed support, temperature, sampling settings, reasoning mode, tool access, context limits, and stopping rules. Exact version unknown means unknown, not inferred from an assistant's self-description. Participant tools should be disabled; trusted harness tooling belongs outside participant context. Proposed generation cap: 4,096 completion tokens per ordinary trial, one attempt, no correction feedback or tool calls. Set the same enforceable cap within a model and record the provider's definition of completion versus reasoning tokens. If an interface cannot enforce or disclose it, mark that trial's budget as uncontrolled; it cannot support the registered budget comparison. Do not assume numerically equal provider token budgets imply equal compute across families. Review worst-case cost before authorizing Round 3: 360 × 4,096 = 1,474,560 completion tokens per family, plus input and any separately billed reasoning. No such spending is authorized by this plan alone.

T10 uses a forced first-leg limit of 256 completion tokens, then a verbatim continuation request with at most 3,840 remaining tokens: total 4,096. An early-complete answer stays in the denominator and is marked early-complete. Forced equal-token cuts do not land at equivalent semantic boundaries across spellings. A deterministic continuation subtask whose supplied reference prefix ends before the same named AST node in every surface would isolate continuation at a semantic cut; it is a separate follow-up, excluded from this pilot's counts and budget until separately registered. Do not pool those two protocols or describe forced generation cuts as semantically matched. Freeze continuation wording and cut manifests before runs.

## Cards, hidden tests, and error handling

Cards cover exactly the same constructs and use examples lowered from the same ASTs. Freeze their text and examples before trials. “One page” or an automatic 2,000-token ceiling must not force one condition to omit necessary complexity. Measure actual card length and separately flag omitted or extra information. Unequal card length is a result; it is not permission to vary semantic instruction coverage.

Parsers accept registered whitespace variation, including CRLF/LF and harmless spaces, and reject only violations of the frozen grammar. D's significant indentation policy must be stated. Do not silently auto-repair closers, add annotations, reorder arguments, insert missing expressions, or modify semantics. Save original bytes even when parsing fails. Register one extraction rule for fenced versus unfenced output, preserve prose, and record extraction failures separately from syntax failures.

Hidden tests and expected outputs must never enter participant prompts or model-readable workspaces. Shared filesystem tools can expose supposedly hidden fixtures accidentally. A trusted runner holds a separate private manifest and executes tests after output capture; participants receive only public examples and task requirements. Publish a timestamped manifest hash before runs, withhold test contents until the cohort is frozen, and release afterward for audit. Hashes alone do not enforce access separation. If the available environment cannot isolate tests, call them public validation tests or defer the claim that they are hidden.

For every assigned trial retain condition/seed/task ID, exact prompt/card bytes, raw completion, model metadata, timestamps, provider finish reason, usage record, extraction outcome, parse diagnostics, type/proof outcome, runtime outcome, and case-level results. Compile/extraction failures count as failed assigned trials for the primary semantic endpoint. Do not compute semantic success only among compilable programs. Also report conditional pass rate among parsable programs as a secondary diagnostic, with its denominator explicit. Transport errors follow a frozen retry policy (at most one identical retry, both attempts retained); model-generated parse failures are not transport errors.

Report separately: assignment-level full-task semantic success; first-attempt extraction/parse/type success; per-case runtime success; proof/refinement acceptance; budget exhaustion; and error categories. Cases within one task and repeated seeds within one task are not independent task samples. Use paired condition differences by task and seed, show task-level results, and quantify uncertainty clustered by task with the limitations of only ten tasks stated. The pilot does not support a confident declaration that close scores are equivalent.

Count actual provider-reported input/output/reasoning usage separately from local tokenizer estimates. `tiktoken` is an estimate for a specified encoding, not an authoritative tokenizer for every family. Record package/encoding/version for every local count. If an appropriate tokenizer or usage field is unavailable, mark it unavailable rather than substituting another family's tokenizer. UTF-8 bytes, Unicode/code-unit counts, lexical tokens, and model tokens are different measures and must remain separate. Count both matched reference renderings and actual generated outputs, labeled accordingly.

## Decision rule and X6

Replace “within noise, smaller card wins” with a pilot outcome of descriptive differences, uncertainty, failure modes, and feasibility. Do not invent an equivalence threshold after inspecting results. Any practical equivalence margin must be justified by the intended use and registered before a separately powered follow-up; the pilot can inform its variance and cost, not retroactively validate the margin. Card size, readability, and generation tokens are secondary outcomes unless an explicit utility function and trade-off weights are approved beforehand.

If the two best surfaces are selected using X1, their later comparison is exploratory selection unless tested on genuinely held-out tasks/seeds in a confirmatory cohort. The fixed D/K secondary arms above avoid this selection step. Neither approach makes ten convenience tasks representative of all programming work.

For X6, freeze claims with known denotations and boundary questions; separate prediction accuracy from confidence and presentation preference. Model-proxy prediction can use fresh one-item contexts with the same metadata controls, but the endpoint is model claim interpretation. Human comprehension requires an actual consenting human protocol, randomized/counterbalanced items, and an analysis that accounts for repeated answers from one person. Hannah is not a statistically interchangeable replicate of a model. No questionnaire or waiting for a human response is requested now. Human results may remain deferred while the model study proceeds under its own label.
