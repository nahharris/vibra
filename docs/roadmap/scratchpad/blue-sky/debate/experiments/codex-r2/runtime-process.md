# Round 2: runtime, process and delivery cross-examination

[measured] Inputs read in this pass: r1-claude.md, r2-claude.md and prior Codex runtime research notes. This is a paper cross-examination, with no new empirical language-performance result. Claude's R1 explicitly says its cited numerical claims were taken from search summaries and remain unverified; none of those numbers is used here as established evidence.

## Concede, with boundaries

- [argued] **R1: accept a reversible safe default, reject raw fewer-concepts as the whole decision rule.** We should converge without implementing every contender. However, one name can conceal several judgments, and a superficially smaller default can freeze an ABI, authority model or recovery format that is expensive to reverse. Instead of retaining every syntax for a future implementation, choose a default now and write its trigger for reopening. **Settlement:** count author decisions, judgment rules, invalid combinations, card size, migration cost and explicit guarantees before comparing defaults; choose the least complex safe option for the present workload, recording uncertainty. **Instead:** amend the proposed rule to 'use the simplest safe, reversible default for the current gate; defer absent concepts; reopen on the stated counterexample or acceptance failure.'
- [argued] **R2: concede removing stage/status/publish overlay API from the first prototype.** File authority and a transaction overlay are orthogonal: a file-based tool can validate many edits atomically, and a cache need not be a source of truth. Thus there was no logical contradiction, but the first CLI does not require a second overlay API. Comparing against the last commit alone is insufficient: dirty files, generated artifacts, protected claim manifests and concurrent modifications can make the checked tree differ from the built tree. **Settlement:** change a file after checking but before building, run on an initially dirty tree, and update both a witness and protected manifest; the resulting artifact must identify exactly what was checked/approved and reject unexpected content changes. **Instead:** use ordinary working copies plus expected file-content hashes, classify changes against the protected claim manifest, and have CI approve/build the exact tested tree/artifact. A source revision can be a tree digest with explicit dirty state; do not equate it with the last commit.
- [argued] **R2 threat precision: signatures belong on the claim boundary, but are not a complete workflow gate.** If an implementer can edit drivers, checker configuration, evidence manifests or CI scripts used to verify its work, an unchanged claim signature does not prevent bypass. This does not justify a full attestation platform for a small local CLI. **Settlement:** name the attacker explicitly and attempt a checker-config/driver/CI bypass under those actual permissions. **Instead:** protect the approval/checking path and relevant configurations for the stated threat model; record tool/driver/policy versions in the built manifest, and keep heavier remote attestation out until it is required.
- [argued] **R3: concede show/find/eval.** Fewer verbs is not itself less complexity; distinct verbs can make distinct operations discoverable. **Settlement:** one small onboarding task can reveal whether a user/agent can find the intended operation without consulting the full catalog. **Instead:** use `show`, `find`, `eval` as ordinary verbs and keep output schemas bounded/versioned rather than merging them for a keyword count.
- [argued] **R4: concede proc-only for the CLI gates.** No current workload requires a durable actor lifecycle. That does not settle whether recursive proc+inbox and explicit reducers have the same useful guarantees. **Settlement:** reopen only when the services gate needs independently arriving commands, overload handling and lifecycle supervision. **Instead:** ship `proc` now; record actor/reducer alternatives and acceptance cases without specifying either prematurely.
- [argued] **R6: concede deferring labels.** Opaque wrappers are useful access controls but do not track data after extraction or control-dependent leakage. Calling them a substitute for noninterference would silently drop a guarantee. **Settlement:** if information-flow claims return, test explicit flow, conditional logging, exceptions/fault visibility and declassification under a named observation model. **Instead:** omit labels and `releases` from the first product, explicitly exclude information-flow security, and use opaque domain values only for the access restriction they actually enforce.
- [argued] **R7: accept recursion/transforms as a provisional default and add the lambda experiment arm.** Tested properties do not make all proof costs disappear: structural totality and safe indexing still need their own rules. Calling loop invariants unnecessary does not prove recursion costs the same; it may move invariants into helper preconditions/accumulators. **Settlement:** compare the same algorithm's obligations and repair effort under the same checker, with required safety/termination checks held fixed. **Instead:** keep the smallest current iteration surface with structural termination inference, label the ergonomics claim unproved, and reopen on real algorithmic friction rather than on cross-language benchmark scores.
- [argued] **R8: accept the criticism of the pilot's K card.** Lexically nested endlet was an experimental treatment choice, not evidence about the proposed statement-sequence keyword surface. **Settlement:** the next cards must hold expression semantics, binding scope, examples and repair affordances constant. **Instead:** use statement `let` in K and report the old pilot only as a harness/procedure smoke test, not as a surface ranking.
- [argued] **R9: accept standard-capability fakes at Gate 1.** Effectful CLI tests need deterministic arguments, console capture and a controlled filesystem view; a lightweight fake is useful before journals or fault simulation. A dictionary filesystem fake is not an OS sandbox and does not by itself cover symlink traversal, permissions, path normalization, quotas or Windows error behavior. **Settlement:** run the same conformance fixtures against fake and real driver for paths, errors and authority boundaries; document deviations. **Instead:** provide in-memory fakes for controlled tests, a small real-driver integration corpus and explicit non-coverage; defer scheduler exploration, journals and failure injection. Do not claim that using a fake proves arbitrary filesystem safety.
- [argued] **R10: accept named method classes only as an index into records.** Sample size without domain/generator/revision/seed/property does not define coverage. A `proved` label is universal only relative to its exact theorem and explicit assumptions; it cannot erase a dependency trust boundary. **Settlement:** ask a policy to distinguish two records with equal sample size but disjoint input domains and to reject a proof with a forbidden assumption. **Instead:** require records with method, property, scope, dependencies and relevant bound/sample metadata; use short labels for display, and predicates over those records for admission.

## Break the merged design where it still overstates

- [argued] **Merged checking: 'every other obligation keeps its runtime check until proved' is too broad.** Nonzero divisors, index bounds and finite refinements can be checked at the operation. A universal quantified postcondition, extensional function equality, liveness property or asymptotic cost statement generally cannot be monitored completely by executing that operation. **Settlement:** classify each proposed obligation by decidability and observation point, then try a universally quantified equality over unbounded inputs. **Instead:** use checked standard-library operations and runtime guards for executable safety predicates; report unproved logical specifications as tested/bounded/assumed without claiming an equivalent runtime monitor. A profile promising no faults must require enough proof for all erased safety guards.
- [argued] **Merged authority: main's parameter types are not the whole authority manifest.** A `FileCap` type may denote an entire filesystem or one read-only directory; a network capability may grant localhost or every endpoint. Host-created root values and their exact configured bounds matter. Captured authority and intents also require a documented representation rule (R5 is addressed separately by the coordinator). **Settlement:** keep main's type unchanged while changing root capability scope and show whether review detects it. **Instead:** main receives root capabilities, while a signed/reviewed manifest states their exact resources, operations, attenuation, delegation and limits, plus bound driver identities. Do not hide 'all files' behind a reassuring type name.
- [argued] **Merged effects: one interface can share syntax without collapsing trusted host interpretation and an untrusted model.** A typed method implemented by a fake and a real driver can have identical signatures but different authority and assumptions. **Settlement:** ensure a test model cannot acquire real effects merely by being selected as an impl. **Instead:** keep one callable interface notation if convenient, but make host imports, pure fakes and target binding explicit semantic/trust categories. Keyword reduction should not erase a trust boundary.
- [argued] **Merged source: a faster definition needs a precise semantic and evidence relationship to the reference.** Finite differential tests establish sampled agreement, not universal interchangeability; reference code can itself have the wrong intended meaning. **Settlement:** include a pair agreeing on every example but differing on an untested boundary. **Instead:** keep the ordinary single definition, report optimization evidence honestly, preserve runtime safety checks independently, and require policy to choose whether tested equivalence suffices for shipping.

## Rebut the remaining R1 runtime statements

- [argued] **c:G1: ephemeral and durable execution do not have identical semantics if crashes/restarts are observations.** They can share ordinary no-fault transition semantics; recovery/loss guarantees differ. [cited] Temporal explicitly distinguishes local activities that bypass normal lifecycle and full durability from regular activities. [Activity execution](https://docs.temporal.io/activity-execution#local-activity-executions). **Settlement:** crash after a committed intent and before its completion under none/ring/durable profiles and compare observable outcomes. **Instead:** define common normal execution plus explicit recovery profiles; say what replay evidence is unavailable when recording is disabled.
- [argued] **c:H2: associativity is not exactly all that a parallel fold needs.** A fold with different accumulator/element types cannot necessarily be split into a reduction. Ordered concatenation is associative but changing leaf order changes its value. Repeating a non-identity initial seed across chunks changes even addition (e.g. seed 10 counted per partition). Side effects, partiality and exceptions/faults add other observations. Floating point may still run in parallel if the grouping tree is specified; it simply cannot promise arbitrary reassociation equals a sequential left fold. **Settlement:** test noncommutative concatenation, non-identity seeds, mixed accumulator/element types and adversarial f64 magnitudes under varied worker counts. **Instead:** specify closure/type, ordering, identity/seed placement, totality and algebraic laws over the admitted domain; alternatively expose a fixed reduction tree with deterministic meaning. A proof of associativity can justify one transformation under stated premises, not the entire parallel API.
- [argued] **c:H3: regular arrays are an excellent first workload, not a requirement for speedup.** Divide-and-conquer and uneven tree traversals can use work stealing; the correct condition is useful independent work exceeding scheduling/data movement costs. [cited] Rayon's parallel iterator API supports map, fold and reduce across its parallel producers, rather than defining parallelism solely by a source array representation. [Rayon API](https://docs.rs/rayon/latest/rayon/iter/trait.ParallelIterator.html). **Settlement:** benchmark irregular tree search and variable-cost parsing alongside tiled arrays. **Instead:** start with bounded ordered map as the small API and measure scheduling granularity; avoid declaring irregular tasks inherently unsuitable.
- [argued] **c:H4: 'WebAssembly threads are weak' has no defined host, feature set or metric.** Native Wasm hosting, browser workers and the selected engine have different available mechanisms and restrictions; a native backend is not logically required for data parallelism. **Settlement:** choose the first actual Wasm engine/host, then measure startup, shared-memory/data-transfer overhead and parallel throughput against its serial path. **Instead:** leave backend parallelism undecided until that target exists and make no performance concession based on an unspecified platform slogan.
- [argued] **c:I: region-per-step plus RC is a candidate, not an exact fit or latency proof.** State, pending continuations, captured values and shared data can outlive a step; promoting them can copy substantial graphs, and decrementing a long structure can cause a long pause. [cited] Lean uses unique reference counts for in-place array mutation and notes that uniqueness can require reasoning beyond a local function. [Lean memory summary](https://lean-lang.org/functional_programming_in_lean/Programming___-Proving___-and-Performance/Summary/#reference-counting-and-in-place-updates). **Settlement:** retain large shared state across steps and drop deep structures while measuring pause and copied bytes. **Instead:** pick the simplest safe memory strategy for the prototype, retain quotas, and defer guaranteed constant update/reclamation costs until measured and specified.
- [argued] **c:J1: drop the second kernel from the initial implementation, not the principle of independent validation.** Two implementations can share mistakes, but an independent checker can still catch implementation errors. 'Kernel computes it itself' does not alone establish the soundness of generated obligations or the semantics of imported primitives. **Settlement:** seed checker defects and compare whether an independent implementation rejects them before considering the added maintenance worthwhile. **Instead:** name the initial trusted base honestly; defer a second implementation to a stronger-assurance gate with an explicit threat/benefit case.
- [argued] **c:K2: agents can use vision tools, and semantic trees cannot replace all visual checks.** An image-capable agent can inspect screenshots; a correct semantic tree can still render overlapped, clipped, invisible or badly scaled controls. [cited] Windows UIA providers expose accessible element semantics, a distinct integration obligation from native rendering. [UIA providers](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview). **Settlement:** inject occlusion, clipping and incorrect DPI layout while leaving the semantic tree unchanged. **Instead:** keep cheap semantic/event tests and add screenshot/layout inspection plus actual keyboard/IME/accessibility checks at the future UI gate; do not claim tests without pixels prove the visible experience.
- [argued] **c:L: fmt should not silently repair ambiguous syntax.** Whitespace normalization is deterministic if a unique parse exists; inventing a missing branch/closer can change intended structure. Also no generic CLI-versus-MCP token ratio is established by the unverified summaries. **Settlement:** feed malformed nested blocks with two plausible repairs and require an explicit parse diagnostic rather than chosen semantics. **Instead:** formatter normalizes parsed programs, offers explicit uniquely mechanical fixes, and leaves ambiguous repairs reviewable. Defer MCP by scope, not by an unverified universal benchmark claim.

## Missing O, P and Q are gates, not slogans

- [argued] **c:O: Wasm components do not supply an ecosystem at once.** Libraries still need compatible interfaces, data conversion, capability imports, deterministic behavior and platform bindings; foreign code remains in the relevant trust boundary. **Settlement:** integrate one real library requiring allocation, callbacks/error handling and IO imports, recording adapter effort and what assurance remains. **Instead:** select one indispensable CLI dependency, expose a narrow typed adapter and document its trust/effect surface; do not promise arbitrary pure-library safety from packaging alone.
- [argued] **c:P: a fresh model predicting claims is not a substitute for human readability.** It can measure one author population, whereas people sign intent and authority. **Settlement:** both agents and the owner independently predict boundary behavior and identify authority/unknowns from the exact claims/manifests, with known correct answers and no body access. **Instead:** keep human prediction and review time as a separate acceptance metric, not an LLM proxy or a taste veto.
- [argued] **c:Q/N: baseline success/failure thresholds must name a mechanism, budget and stopping rule.** Twenty tasks can discover a disastrous design but cannot establish broad general-purpose superiority; searching many surfaces then reporting the winner on the same tasks overfits. A failed language-wide comparison may still vindicate its workflow tools. **Settlement:** predeclare representative CLI tasks, held-out cases, equal information/tool feedback, token/dollar/wall-time budgets, repeat count and acceptable complexity; report failures and uncertainty. **Instead:** gate the specific next investment (syntax, checker loop, capability boundary or runtime), keep a held-out evaluation set, and stop/redesign that mechanism when it fails. Do not treat every noisy failure as proof that all of Vibra is wrong, or every successful microbenchmark as permission to build the full proposal.
