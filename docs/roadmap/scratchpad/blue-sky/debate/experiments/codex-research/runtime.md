# Runtime, authority, parallelism and native UI adversarial notes

[measured] Scope: this independent Codex research pass read the debate protocol, blue-sky README, paradigms, tooling, draft spec README, 00, 03, 05, 06, 07, 08 and relevant portions of 04 and 09. It did not read Claude review artifacts. This is research and a toy protocol experiment, not execution of a Vibra implementation. Date: 2026-11-15.

## F and G: Does the execution model carry the guarantees claimed?

### Takeaway

[argued] A pure transition function plus durable outbox is a valuable service architecture. It does not by itself supply resource-scoped authority, effect polymorphism, cancellation semantics, external exactly-once execution, or safe upgrades. Keep it as a constrained execution profile and specify the missing protocols before claiming these guarantees.

### Cited Findings

- [cited] The draft already distinguishes `once` operations returning `uncertain` from repeatable operations, requires durable intent/commit before driver invocation, and records driver-model violations. It should receive credit for addressing the ordinary crash ambiguity; accusing it of claiming universal exactly-once would misread the later specification. [Delivery](../../../spec/05-execution.md#delivery), [journal format](../../../spec/06-runtime.md#journal-format).
- [cited] Temporal describes the crash after external execution but before its completion is reported, requires idempotent business operations, and states that idempotency keys are enforced by the called service. This is direct precedent for retaining uncertainty rather than pretending journal positions solve external atomicity. [Temporal activity definition](https://docs.temporal.io/activity-definition).
- [cited] Temporal cancellation is a notification: activities may accept or ignore it, and a workflow may wait for acceptance or proceed. [Temporal activity cancellation](https://docs.temporal.io/activity-execution#cancellation).
- [cited] Pony defines an object capability as an unforgeable reference designating an object and authorizing operations; derived authority is explicitly restricted before delegation. Its documentation also says removing globals alone is insufficient to remove ambient authority. [Object capabilities](https://tutorial.ponylang.io/object-capabilities/object-capabilities.html), [derived authority](https://tutorial.ponylang.io/object-capabilities/derived-authority.html).
- [cited] Lingua Franca uses logical time plus microsteps so that a zero-delay action occurs at the same instant one microstep later. Physical actions are assigned using physical arrival time. [Superdense time](https://www.lf-lang.org/docs/writing-reactors/superdense-time/), [physical actions](https://www.lf-lang.org/docs/writing-reactors/actions/#physical-actions).

### Inferences

- [argued] **F1: `uses ledger` is an effect allowlist, not yet a least-authority capability design.** The draft does not explain how one caller grants only one account, one directory, one tenant, one operation or one spend limit, nor attenuation, revocation, or serialized address forgery. The latter matters because addresses may be stored as values. Experiment: give an untrusted plugin read authority over directory A and adversarially attempt path traversal, symlink escape, serialization forgery, delegation, and writes. Change my mind when the checker and driver reject each unauthorized path under a documented authority model. **Instead:** keep `uses` for summary and pass unforgeable, attenuated resource handles for authority; retain host enforcement at the driver boundary.
- [argued] **F2: `(intent t)` omits the ports that performing it may address.** Pure functions may build intents without `uses`, while callers may receive intents through parameters or higher-order functions. An opaque result type alone cannot express which ports are hidden in returned composite data. Experiment: abstract a ledger intent behind a function claim returning `(intent unit)`, pass it to an audit-only procedure, and require rejection without unfolding the witness. **Instead:** add a statically checked effect index such as `intent<ports, result>`, or explicitly specify a sound provenance system with equivalent information. Do not make safety depend on inspecting opaque witnesses.
- [argued] **F3: banning user handlers is not a security proof.** An interpreter over pure effect-request data is safe if its outer authority is constrained; the dangerous component is unrestricted access to real drivers. Experiment: compare a pure deterministic test handler with the mandatory port-model mechanism on the same tasks. **Instead:** keep real effect execution behind host-controlled capabilities, use one model/handler mechanism for pure interpretation, and defer general handler syntax until needed.
- [argued] **G1: cancellation loses information about external effects.** `intent.first` says the loser is cancelled; `intent.within` reports only `none`. A timeout after an external debit committed can return `none` while money moved; retrying under a fresh key can then move it twice. This remains true without a process crash. The small experiment below demonstrates this conditional protocol fact. Experiment that would settle design: enumerate cancellation before dispatch, after dispatch, after external commit, and after outcome commit for repeatable and once drivers, with late replies and restart. **Instead:** distinguish cancellation requested, cancellation confirmed before effect, completed, and uncertain; keep a receipt/reconciliation handle for every dispatched operation. Timeout ends waiting, not the fact that the operation may have happened.
- [argued] **G2: at-most-once dispatch still needs a durable dispatch state.** A committed intent followed by a crash before, during or after dispatch cannot be safely retried merely because its key exists. Marking dispatch durably before sending gives possible omission and unknown; marking afterward risks duplication. Experiment: crash at each instruction boundary around durable marking, send, external commit, and response commit. **Instead:** define a durable dispatch lifecycle and report unknown after ambiguous once dispatch; permit repeatable dispatch only with sink-enforced deduplication and a retention period.
- [argued] **G3: repeatable model semantics are missing a key/history contract.** The sample refund adds money and audit record appends an entry; their model handlers see arguments, not a documented idempotency-key cache. `repeatable` in 06 allows the same outcome or one the model allows as a repeat, weakening 05's same-request requirement. Equal outcome values do not prevent a second external write. Experiment: replay a refund key twice and check both model state and real balances, including after compaction/restart. **Instead:** make operation identity and persistent deduplication explicit in runtime/model semantics, with payload-mismatch rejection and expiry policy; do not test only return-value equality.
- [argued] **G4: deterministic replay is conditional on recorded external choices.** Tag ordering does not make fresh physical arrivals deterministic, and ordering equal-instants by address is not a complete rule for newly emitted zero-delay messages or late arrivals. Infinite zero-delay self-messages can starve future timers even if every handler terminates. Experiment: two machines at one instant, each sending to the lower address; delayed physical signals; a zero-delay self-loop; verify causal order and progress. **Instead:** distinguish replay determinism from live nondeterminism, add causal microsteps, monotone tag assignment, late-event policy, and a budget for same-instant progress. Start with one local sequencer; do not promise distributed ordering without coordination.
- [argued] **G5: `proc` and `machine` should share semantics but not be indiscriminately collapsed.** Procedures are useful for finite workflows; explicit machines are useful for independently arriving commands and lifecycle. Actors are not a data-parallel programming model and message passing alone does not prove absence of cyclic waits. Experiment: implement the same transfer, streaming importer, and interactive editor both ways; measure generated state size, obligations, repair effort, and deadlocks. **Instead:** use procedures as the common surface, retain explicit machines for long-lived ownership, and offer structured child lifetimes plus bounded mailboxes.
- [argued] **G6: witness replacement at the next step is unsafe for derived continuations without a version rule.** A new direct-style body may add or reorder awaits, change captured locals or pending-operation sources even when its result claim is unchanged. Replaying an arbitrary new cell may not accept the old event schema, so Against/What-if cannot literally never fail. Experiment: upgrade while suspended at each await, with old pending replies delivered afterward. **Instead:** pin a procedure version per live instance or require an explicit continuation migration, record the version epoch in the journal, and return typed incompatibility from replay modes.

### Gaps

- [argued] No reference runtime exists in this research pass that could establish latency, fsync throughput, actor scaling or safe upgrades. These are proposals requiring benchmarks, not measured Vibra benefits. **Instead:** prototype one local durable workflow and benchmark it against an ordinary checked host-language implementation before expanding the substrate.

## H and I: Is parallelism fearless and the runtime feasible?

### Takeaway

[argued] Purity removes shared-memory data races from ordinary values; it does not guarantee speedup, bounded memory, responsive scheduling, safe resource reclamation, or deterministic reductions. Make bounded parallelism an explicit library contract, and keep runtime quotas even when programs are mathematically total.

### Cited Findings

- [cited] Rayon exposes parallel iterators, including map, fold, reduce and ordered versus unordered find operations, with Send/Sync requirements. This is a concrete existing-library baseline for useful data parallelism. [Rayon ParallelIterator](https://docs.rs/rayon/latest/rayon/iter/trait.ParallelIterator.html).
- [cited] Python task groups await their related tasks on context exit, providing an explicit lifetime scope. [asyncio task groups](https://docs.python.org/3/library/asyncio-task.html#task-groups).
- [cited] Pony documents message-queue growth when senders outpace receivers and runtime backpressure that temporarily mutes senders. Actors need an explicit overload mechanism even in a language designed around safe actors. [Pony backpressure](https://tutorial.ponylang.io/runtime-basics/backpressure.html).
- [cited] Lean's documented in-place array reuse occurs when the reference count is one; understanding uniqueness can require whole-program knowledge. [Lean reference counting and in-place updates](https://lean-lang.org/functional_programming_in_lean/Programming___-Proving___-and-Performance/Summary/#reference-counting-and-in-place-updates).

### Inferences

- [argued] **H1: pure evaluation permits parallelism; it does not supply it.** Add deterministic `parallel-map` with bounded workers/grain, ordered output, scoped cancellation, and explicit sequential fallback. Add reductions only with fixed grouping or a checked associative operation; floating point sum must not silently reassociate. Experiment: image tiles, parser batches, map/reduce over tiny and large elements, and nested parallel maps on 1/2/4/8 workers, measuring time, peak memory and output identity. **Instead:** implement this small library surface before actors, automatic parallelization or a new execution calculus.
- [argued] **H2: `intent.all items` can launch an unbounded number of effects.** No admission credits, bounded concurrent map or child supervision/cancellation completion semantics are given. A million safe requests can exhaust queues or overload a service. Experiment: a fast producer, slow receiver, saturated sink, child fault and parent cancellation; assert fixed queue bounds and eventual shutdown. **Instead:** provide scoped task groups and `map-concurrent limit`, mailbox capacity/credit rules and explicit overload outcomes; require a configured limit on all fan-out.
- [argued] **I1: a tested or assumed cost claim is not a scheduler guarantee.** Even a proved symbolic bound may be astronomically large, and one step of big-integer arithmetic can consume unbounded wall time or memory when integer size is unbounded. Non-preemption therefore does not follow from totality. Experiment: a large terminating Fibonacci/reference search, a huge integer multiplication, a deep destructor, and an invalid staged draft; verify other instances and tool cancellation remain responsive. **Instead:** enforce fuel, memory, wall-time and output quotas at evaluator boundaries; separate mathematical totality from service latency and allow cooperative internal yielding without observable program interleaving.
- [argued] **I2: the memory contract overpromises.** Consuming one binding does not prove no alias exists because values are shared freely; in-place update cannot preserve immutability through aliases. Reference counting can trigger a long cascading decrement, and freeing a whole region can scale with region size. Persistent machine state can also outlive a per-step region. Experiment: alias an array before passing it to `own`, retain old version through a closure, and drop a long linked structure during a short handler. **Instead:** prove uniqueness with an ownership/borrowing or explicit unique-reference discipline, allow copy-on-write for shared values, and specify bounded incremental reclamation rather than declaring RC or regions sufficient.
- [argued] **I3: exploration must hash the whole future-relevant configuration.** Equal user state can conceal different pending intents, mailbox events, timer sets, port-model states, dispatch/dedup states, child lifetimes and upgrade epochs. Memoizing only user state can prune an error path. Environment models remain separate abstractions even when the application step function is the explored program. Experiment: two paths yielding identical application state with different pending debit outcomes; verify both futures are explored. **Instead:** define the configuration state and canonicalization explicitly, including scheduler queues and model state; report depth, domain and environment assumptions with evidence.
- [argued] **I4: journals have an economic and privacy contract.** Mandatory recording of every inbound/outbound value duplicates large media and secret material; snapshot/discard can destroy replay or pending-key dedup information. A bare hash chain can be wholly rewritten if no expected head is anchored elsewhere. Experiment: durable-vs-memory throughput and p50/p99 latency, bytes per event, recovery time at increasing log sizes, redacted export, key rotation and truncation of outstanding work. **Instead:** distinguish durable, replayable ephemeral and volatile targets; journal normalized semantic input plus content hashes, use anchored checkpoints and encryption policy, and specify compaction preserving pending operations and idempotency history.

### Gaps

- [argued] No published paper cited by the draft proves its exact mixture of total language, cost model, journaling, implicit derived frames, labels and portable floating point meets its performance promises. **Instead:** require a measured budget for each cross-cutting guarantee rather than treating compatible individual mechanisms as evidence for the complete system.

## K, L and N: What should ship, and what would native UI mean?

### Takeaway

[argued] Native graphics is feasible behind typed host drivers without a browser, including a native host running Wasm. A pixel renderer is not a complete native UI. Ship an intentionally small agent toolchain and one useful execution path before custom widgets or a universal replaying desktop runtime.

### Cited Findings

- [cited] Standard Windows controls have UI Automation providers; custom controls require providers implementing accessibility and control-pattern interfaces. [Microsoft UI Automation providers](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-providersoverview).
- [cited] Windows Text Services Framework supports advanced multilingual text input, keyboard processors, handwriting and speech services. [Microsoft TSF](https://learn.microsoft.com/en-us/windows/win32/tsf/text-services-framework).
- [cited] The draft's tooling chapter lists 18 command verbs and permits one MCP tool per command, although the accompanying tooling note recommends five verbs and narrow tooling. Its eval contract permits invalid staged overlays/holes while saying pure evaluation needs no sandbox. [Draft tooling](../../../spec/08-tooling.md), [tooling direction](../../../tooling.md).

### Inferences

- [argued] **K1: no-webview does not justify building an entire widget toolkit.** A custom renderer inherits focus, keyboard navigation, selection, bidirectional text, font fallback, accessibility, DPI, IME composition and platform integration. Experiment: a resizable text editor with Chinese/Japanese composition, Portuguese dead keys, emoji selection, screen reader navigation, high DPI, clipboard, file picker and keyboard-only use. **Instead:** start with Windows native-control drivers and a pure declarative view/event API; offer a separate canvas port for graphics. Keep UIA/TSF and OS handles inside the driver boundary, with resource-scoped authority.
- [argued] **K2: pixel determinism conflicts with portable native rendering unless its scope is narrowed.** OS font fallback, GPU APIs and DPI vary, whereas 00 requires determinism across evaluators/backends. Mandatory fsync for every pointer move or display update is also a latency cost, not a free debugging feature. Experiment: record/replay the same interaction on two machines with different fonts, DPI and GPU; distinguish scene/event identity from pixels. **Instead:** guarantee deterministic application state and normalized draw/view descriptions, test rendering separately with a pinned software renderer if pixel identity is needed, and use opt-in bounded recording for high-frequency UI events. Journal resources by immutable content hash rather than every pixel.
- [argued] **L1: exact minimal initial CLI:** `check`, `eval`, `show`, `find`, `stage`, `status`, `publish`; add `run` only with an actual runtime. `check` includes type, termination and explicit obligation statuses; eval has revision/fuel/memory/output limits; show includes claims, debts and one example; find searches typed signatures plus text; stage supports temporary invalidity and gives a bounded dependency worklist; publish is compare-and-swap atomic with authorization. Keep sources in stdin/files and provide a versioned machine output envelope. Experiment: equal-task/equal-budget ablations against shell plus checker, especially multi-file signature repair and invented-library calls. **Instead:** ship this seven-command core, a generated one-page language/API card, stable diagnostics, text projections, formatter/parser integration, and a single thin MCP dispatch adapter only when an actual client needs it.
- [argued] **L2: pushed facts need an output budget, not an unlimited completeness promise.** In a high-fanout dependency graph every broken dependent and every in-scope typed value may exceed useful context. A language design cannot guarantee every possible fix is already in one bounded diagnostic. Experiment: 10,000 dependents and 1,000 type-compatible candidates; measure one-turn repair with ranked summaries vs full output. **Instead:** return bounded ranked facts, stable IDs, continuation cursors and precise remainder counts, with a deterministic way to ask for the rest. Interpret complete-in-itself as sufficient to understand the immediate failure, not omniscient repair advice.
- [argued] **L3: promoting an evaluation is regression evidence, not independent intent evidence.** Recording an agent's own output as expected can canonize its bug. Experiment: seed a plausible wrong result and compare automatic promotion vs intent-authority confirmation and hidden tests. **Instead:** attach provenance and require separate approval before a kept result changes the protected claim; keep observed-result fixtures distinguishable from externally supplied expectations.
- [argued] **N1: the smallest useful release should challenge the need for the whole language.** Build a pure typed reference core, totality subset, checked examples, machine-readable diagnostics, staged transactions, and bounded eval. In parallel use a conventional language with immutable data, contracts/read-only tests and the same tool loop on the same workload. Choose a single practical workload: a durable job/transfer service with crash/retry simulation, or a bounded pure data-processing library. Do not require both plus native UI, linear capabilities, labels and proof certificates at once. Experiment: blinded hidden-task success per dollar and wall time, specification accuracy, maintainer changes, and failure recovery at a preregistered acceptable cost. **Instead:** fund only the smallest profile that beats the baseline, and cut the language proposal if its tooling/runtime supplies the benefits equally well in the host language.

### Gaps

- [argued] Native UI semantics and concrete driver ABI are absent from the reviewed draft, and there is no local performance evidence for the proposed UI path. A source describing another framework cannot establish Vibra feasibility/cost. **Instead:** treat a native editor slice as a later feasibility prototype with an accessibility/text-input exit gate, not a promised core language guarantee.

### Raw protocol experiment: timeout is not effect rollback

[measured] Method: a PowerShell enumeration of four placements of `timeout` around an ordered sequence `dispatch < charge < response`. Dispatch is skipped if timeout was already observed. Once dispatched, the external charge is non-cooperative and commits even if the caller times out. A timeout changes the caller outcome from pending to none; a response changes pending to known. No probability distribution, real driver, Vibra runtime or performance claim is implied. These four linearizations are exhaustive for this deliberately tiny model only.

```powershell
$traces = @(
  @('timeout','dispatch','charge','response'),
  @('dispatch','timeout','charge','response'),
  @('dispatch','charge','timeout','response'),
  @('dispatch','charge','response','timeout')
)
$rows = foreach ($trace in $traces) {
  $dispatched = $false; $charged = $false; $outcome = 'pending'
  foreach ($event in $trace) {
    switch ($event) {
      'dispatch' { if ($outcome -eq 'pending') { $dispatched = $true } }
      'charge' { if ($dispatched) { $charged = $true } }
      'response' { if ($dispatched -and $outcome -eq 'pending') { $outcome = 'known' } }
      'timeout' { if ($outcome -eq 'pending') { $outcome = 'none' } }
    }
  }
  [pscustomobject]@{trace=($trace -join ','); outcome=$outcome; external_charge=$charged}
}
$rows | ConvertTo-Json
[pscustomobject]@{
  linearizations=$rows.Count
  timeout_with_charge=@($rows | Where-Object {$_.outcome -eq 'none' -and $_.external_charge}).Count
} | ConvertTo-Json
```

[measured] Raw output from actual execution:

```json
[
  {"trace":"timeout,dispatch,charge,response","outcome":"none","external_charge":false},
  {"trace":"dispatch,timeout,charge,response","outcome":"none","external_charge":true},
  {"trace":"dispatch,charge,timeout,response","outcome":"none","external_charge":true},
  {"trace":"dispatch,charge,response,timeout","outcome":"known","external_charge":true}
]
{"linearizations":4,"timeout_with_charge":2}
```

[argued] Interpretation: two allowed traces in this toy model return timeout with an external effect. This establishes a counterexample to interpreting timeout as proof of no effect; it does not establish that an implemented Vibra runtime is defective. A documented driver protocol prohibiting these traces would change the applicability of the counterexample. **Instead:** specify completion/cancellation/uncertainty explicitly and preserve a reconciliation handle.

### Supplemental synthesis requested by coordinator

- [argued] **Journal scope is contradictory enough to block a scheduler contract.** 06 defines each instance as one machine/procedure with its own journal, then a system sharing one tag order; 05 Open says one journal per runtime instance, while root architectural language often speaks of the whole application journal. Neither a total order across independently persisted journals nor atomic cross-instance message delivery follows from each log's own commit. Experiment: crash the sender after its intent commits and the receiver before/after its event commits; assert durable delivery/dedup and replay of the entire system. **Instead:** begin with one system journal/sequencer and explicitly partition it later, or specify cross-journal message/outbox identities and recovery before claiming a single system order.
- [argued] **MVP command detail can be reduced further by separating actions and query modes.** `check` (including selected conformance/examples, or a `test` mode), `eval`, `show` (including lookup modes), `stage`, `status`, and `publish` form a six-verb evaluation candidate, not a proven optimum. A dedicated `test` can be justified for conventional discovery if it earns an extra verb. `run` arrives only with a useful effectful prototype. Every response needs pinned revision, tool/schema version, stable identifiers, truncation metadata and exact check/evidence status; reproducibility excludes timestamps or seeds from semantic output unless explicitly supplied/recorded. Experiment: randomize the same tasks across six-verb, seven/eight-verb and current 18-verb catalogs with tool descriptions held constant in substance. **Instead:** use the smallest discoverable catalog that preserves explicit boundaries and measure it; do not optimize the number of verbs as a proxy for cognitive complexity.
- [argued] **The early comparison need not commit to an authoritative object store.** Hash files/declarations and evidence manifests while ordinary version-controlled files remain authoritative; protected claim manifests and staged worktrees can test separation of powers and atomic review. Store implementation costs should be measured only if file/worktree baselines fail on identity, collaboration or evidence reuse. Experiment: identical edits, concurrent branches, renames and claim/witness swaps under a file-authoritative pilot versus a store prototype, measuring lost work, migration effort and total agent tokens. **Instead:** make the first experiment file-authoritative and retain hashes as cache keys, postponing store authority until evidence supports it.
- [argued] **Native UI fork:** a host native toolkit can expose a semantic widget tree, with its ordinary accessibility/text integration; a custom canvas renderer must supply its own semantic/accessibility tree and UIA/TSF integration. Both can host Wasm without a webview. Experiment: perform the same text/focus/accessibility acceptance slice on both. **Instead:** start with the native-toolkit semantic-tree host, keep custom drawing as an optional canvas, and promise deterministic state/commands rather than identical native pixels.
