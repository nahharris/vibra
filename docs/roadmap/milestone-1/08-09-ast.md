# Steps 8 and 9 — contextual AST and formatting

Prerequisites: Steps 5–7. Read source **Declarations**, **External definitions**,
**Functions and expressions** (the expression grammar), **Type ascription and
narrowing**, and **Canonical format**; type-system **Nominal declarations** and
**Generics**; effects declaration rules; diagnostics registry and recovery.

## Shared structure

Add proposed AST modules for declarations, types, expressions, and patterns.
Use checked CST views or nodes retaining CST identities and original spans.
Share cursor utilities, but dispatch explicitly by grammar context. Keep
recovery nodes visible and propagate invalidity without discarding intact
sibling declarations. Do not assign a valid typed view to an ambiguous subtree.

First write a context/head/arity/allowed-label table from the normative grammar.
Use it for validation, formatting, and Step 10 metadata. Close missing diagnostic
contracts before implementing their error paths. Do not introduce new public
JSON AST schemas merely to test internal nodes.

## Step 8: declarations and types

1. Recognize the seven top forms explicitly. Give `deftype`, `defint`, `deffect`,
   and nested `impl` native variants. Store ownership/nesting structurally;
   do not lower them to generic calls or infer canonical resolved identities.
2. Validate fixed headers before collecting attributes. Add checked flat-pair
   and flat-triple helpers: positional pattern/type pairs, labelled
   name/type/literal-default triples, generic name/bound pairs, and one variadic
   binder/type pair. Validate array/map variadic type shape. Preserve pattern
   and body CST references for Step 9 rather than pretending they are validated.
3. Add a distinct `deftype-body` parser and ordinary `type-expr` parser. The four
   nominal body heads are allowed only at that body position. Reserved type
   heads dispatch before applied-type fallback, including nested type operands.
4. Validate allowed attributes, duplicates, missing values, and member placement.
   Preserve references in effect rows as symbols; atoms there use the specified
   `@effect.invalid-reference`. Validate syntactic external/body relationships;
   provider ownership and registry signature checking remain later work.
5. Format fixed headers, attributes in canonical order, then methods and impls.
   Reorder complete attribute/value groups with their comments, not bare leaves.
   Never move a label out of a malformed fixed header to make it valid.

Required tests: every top form; empty permitted bodies; nested methods and impls
under each legal owner; illegal top-level impl; qualified declaration names;
missing header fields; odd pairs/incomplete triples; duplicate/unknown
attributes; wrong attribute position; malformed variadic shape; generic bounds;
function types versus functions; record/enum flat pairs; union minimum arity;
newtype arity; anonymous type bodies in parameter/result/field/impl positions.
Keep a legal nested method named `map` regression: reserved type-head rules
must not spread into unrelated member namespaces.

Step 8 completion claims declaration/type structure only. Full expression and
pattern grammar remains explicitly assigned to Step 9. Union overlap, abstract
member completeness, inference, visibility resolution, and effect propagation
remain later-milestone semantic checks.

## Step 9: expressions, patterns, and applications

1. Parse reserved expression heads before generic application. Parse reserved
   pattern heads before constructor patterns. Implement `as` separately in both
   contexts with a full type expression and exactly one operand/pattern.
2. Complete the expression and pattern interiors retained by Step 8. Validate
   flat match pattern/result pairs, direct let patterns, lambda attributes, and
   each control form's required operands using the canonical grammar.
3. Keep arbitrary callee forms in nonempty applications, including list heads.
   Reject executable empty lists while preserving contextual empty parameter
   and effect lists. Do not emit type-not-applicable merely from parser shape.
4. Recognize explicitly retired constructs and emit `@syntax.retired-form`;
   do not allow them through generic-call fallback. Validate discard roles in
   binders/wildcards and reject discard values/references. Shadowing and
   irrefutability require later semantic analysis.
5. Preserve argument groups and their spans in written order. Close the supplied
   binding-facts contract from [implementation.md](implementation.md) before
   reordering labelled/variadic arguments. With authoritative binding facts,
   emit fixed operands, declaration-order labels, then variadic source order.
   Without them, never guess declaration order or claim canonical binding.
6. Format multiline match arms as pattern/result units and preserve comment
   attachment. Prove normalized AST equivalence after formatting, excluding
   source positions/trivia and only those presentation differences explicitly
   normalized by the contract.

Required tests: `as` in expression and pattern contexts, bad arity and nested
type bodies; list-headed application; valid syntax with unresolved callees;
empty application versus empty parameter list; nested patterns; repeated
discards versus discard values; missing match result; retired wrappers/forms;
duplicate and unknown labels where binding facts are available; labelled and
variadic normalization with array and map tails; comments beside moved groups.

For signature-dependent tests, use explicit supplied signatures and their real
binding/formatting path, never a mock that returns expected formatted text.
Record which normalization evidence is possible in `reader-v1` and which needs
the resolved contract; an unresolved allocation prevents M1 gate completion.

Both steps add host structure/error tests and reader corpus cases, preserve all
Step 4 formatting/recovery regressions, and run [validation](validation.md).
